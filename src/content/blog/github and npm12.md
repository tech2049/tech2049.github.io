# npm چیست؟ بررسی کامل اسکریپت‌های npm و تغییرات امنیتی جدید GitHub (راهنمای جامع 2026)

## مقدمه

اگر در دنیای جاوااسکریپت و Node.js فعالیت می‌کنید، احتمالاً نام npm را بارها شنیده‌اید. اما چیزی که بسیاری از توسعه‌دهندگان از آن غافل هستند، خطرات امنیتی مرتبط با اسکریپت‌های npm است.

در این مقاله به‌صورت کامل بررسی می‌کنیم:

* npm چیست و چگونه کار می‌کند
* اسکریپت‌های npm چه هستند
* چرا اسکریپت‌های نصب خطرناک شدند
* بررسی یک حمله واقعی (event-stream)
* تغییرات جدید GitHub در npm برای افزایش امنیت
* بهترین روش‌های امن استفاده از npm

---

## npm چیست؟ (Node Package Manager)

npm مخفف Node Package Manager است و به عنوان مدیر پکیج برای Node.js استفاده می‌شود.

به زبان ساده:
npm یک مخزن بزرگ از کتابخانه‌های جاوااسکریپتی است که توسعه‌دهندگان می‌توانند از آن‌ها در پروژه‌های خود استفاده کنند.

### کاربردهای اصلی npm:

* نصب پکیج‌ها
* مدیریت وابستگی‌ها (Dependencies)
* اجرای اسکریپت‌ها
* مدیریت نسخه‌ها

---

## ساختار پروژه در npm

هر پروژه npm معمولاً شامل فایل‌های زیر است:

### 1. package.json

فایل اصلی پروژه که شامل:

* اطلاعات پروژه
* لیست وابستگی‌ها
* اسکریپت‌ها

### 2. node_modules

محل نصب تمام پکیج‌ها

### 3. package-lock.json

برای قفل کردن نسخه دقیق پکیج‌ها و جلوگیری از ناسازگاری

---

## اسکریپت‌های npm چیست؟

در فایل package.json بخشی به نام scripts وجود دارد که برای اجرای دستورات استفاده می‌شود.

```json
{
  "scripts": {
    "start": "node index.js",
    "build": "webpack",
    "test": "jest"
  }
}
```

با استفاده از این اسکریپت‌ها می‌توانید دستورات پیچیده را ساده اجرا کنید:

```bash
npm run build
```

---

## اسکریپت‌های نصب (Lifecycle Scripts)

npm دارای اسکریپت‌هایی است که به صورت خودکار هنگام نصب اجرا می‌شوند:

* preinstall
* install
* postinstall

این اسکریپت‌ها هنگام اجرای دستور زیر فعال می‌شوند:

```bash
npm install
```

---

## مشکل امنیتی npm از کجا شروع شد؟

مشکل اصلی از اینجا شروع می‌شود:

وقتی npm install اجرا می‌شود:

* تمام وابستگی‌ها نصب می‌شوند
* اسکریپت‌های تمام آن‌ها (حتی وابستگی‌های غیرمستقیم) اجرا می‌شوند

### نتیجه:

اگر حتی یک پکیج آلوده باشد، می‌تواند روی سیستم شما کد اجرا کند.

---

## Supply Chain Attack چیست؟

حمله زنجیره تأمین (Supply Chain Attack) زمانی رخ می‌دهد که:

شما به یک پکیج اعتماد دارید
آن پکیج به یک پکیج دیگر وابسته است
پکیج دوم آلوده است

در نتیجه شما بدون اینکه بدانید در معرض حمله قرار می‌گیرید.

---

## مثال واقعی: حمله event-stream

یکی از معروف‌ترین حملات npm مربوط به پکیج event-stream بود.

### روند حمله:

1. پکیج بسیار محبوب بود
2. توسعه‌دهنده اصلی آن را رها کرد
3. یک فرد دیگر آن را مدیریت کرد
4. یک وابستگی مخرب اضافه شد

### هدف حمله:

سرقت اطلاعات کیف پول‌های ارز دیجیتال

### نکته مهم:

این حمله از طریق وابستگی‌های غیرمستقیم انجام شد.

---

## چرا این حمله موفق بود؟

چون npm به صورت پیش‌فرض:

* اسکریپت‌ها را اجرا می‌کرد
* به همه پکیج‌ها اعتماد داشت

این یعنی هر پکیج می‌توانست:

* کد اجرا کند
* به اینترنت متصل شود
* اطلاعات سیستم را بخواند

---

## تغییرات جدید GitHub در npm (نسخه 12)

برای حل این مشکلات، GitHub تغییرات مهمی در npm ایجاد کرده است.

### 1. غیرفعال شدن اجرای خودکار اسکریپت‌ها

دیگر این اسکریپت‌ها به صورت پیش‌فرض اجرا نمی‌شوند:

* preinstall
* install
* postinstall

---

### 2. محدودیت وابستگی‌های Git

نصب پکیج از Git:
❌ به صورت پیش‌فرض غیرفعال
✅ نیاز به --allow-git

---

### 3. محدودیت دانلود از URL

نصب از لینک مستقیم:
❌ غیرفعال
✅ نیاز به --allow-remote

---

### 4. محدودیت buildهای native

پکیج‌هایی که از node-gyp استفاده می‌کنند نیز:

* نیاز به تأیید دارند

---

## دستور جدید npm: approve-scripts

برای مدیریت اسکریپت‌ها:

```bash
npm approve-scripts
```

### کاربرد:

* نمایش پکیج‌هایی که اسکریپت دارند
* تأیید پکیج‌های قابل اعتماد
* افزایش امنیت پروژه

---

## مفهوم امنیتی Opt-in

در گذشته:
همه چیز فعال بود (Opt-out)

اکنون:
همه چیز غیرفعال است تا شما فعال کنید (Opt-in)

این مدل امنیتی بسیار امن‌تر است.

## بهترین روش‌های امنیتی در npm

### 1. استفاده از پکیج‌های معتبر

قبل از نصب، پکیج را بررسی کنید.

### 2. بررسی وابستگی‌ها

از ابزارهایی مثل npm audit استفاده کنید:

```bash
npm audit
```

### 3. استفاده از --ignore-scripts

در موارد حساس:

```bash
npm install --ignore-scripts
```

### 4. بررسی اسکریپت‌ها

فایل package.json را بررسی کنید.

### 5. قفل کردن نسخه‌ها

از package-lock.json استفاده کنید.

## جمع‌بندی

npm یکی از مهم‌ترین ابزارهای توسعه جاوااسکریپت است، اما همین ابزار می‌تواند به یک نقطه ضعف امنیتی تبدیل شود.

تغییرات جدید GitHub در npm، یک تحول مهم در افزایش امنیت اکوسیستم جاوااسکریپت است. با تبدیل اجرای اسکریپت‌ها از حالت خودکار به اختیاری، بسیاری از مسیرهای حمله بسته می‌شوند.

در نهایت، امنیت به دانش و آگاهی توسعه‌دهنده بستگی دارد. هرچه بیشتر درباره ابزارهای خود بدانید، پروژه‌های امن‌تری خواهید داشت.

## سوالات متداول (FAQ)

### آیا npm امن است؟

بله، اما باید با آگاهی استفاده شود.

### آیا همه اسکریپت‌ها خطرناک هستند؟

خیر، اما باید فقط به اسکریپت‌های قابل اعتماد اجازه اجرا داد.

### آیا باید اسکریپت‌ها را کامل غیرفعال کنیم؟

نه، فقط باید آن‌ها را مدیریت و بررسی کنیم.
